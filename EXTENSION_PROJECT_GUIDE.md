# EXTENSION_PROJECT_GUIDE.md
# Guia para Desenvolvimento de Projetos de Extensão
Este documento define a estrutura de referência para o desenvolvimento dos projetos de extensão da disciplina **Atividades de Extensão I**.
Seu objetivo é orientar a geração de todos os materiais didáticos relacionados ao projeto, garantindo uma metodologia consistente independentemente da modalidade escolhida.
Este guia **não define um tipo específico de projeto**. Ele descreve um processo que pode ser aplicado a diferentes modalidades de extensão.
---
# Princípios
Todo projeto de extensão desenvolvido na disciplina deve:
- atender uma demanda real da comunidade;
- estabelecer interação entre instituição e sociedade;
- aplicar conhecimentos desenvolvidos no curso;
- proporcionar aprendizagem significativa aos estudantes;
- produzir benefícios para os participantes;
- permitir documentação e avaliação de resultados.
O foco da disciplina não é apenas produzir um artefato ou realizar uma atividade, mas vivenciar todo o ciclo de um projeto extensionista.
---
# Ciclo do Projeto
Todo projeto desenvolvido na disciplina deve percorrer as seguintes etapas.
```
Identificação
      ↓
Planejamento
      ↓
Preparação
      ↓
Execução
      ↓
Documentação
      ↓
Avaliação
      ↓
Reflexão
```
As etapas podem se sobrepor parcialmente, mas todas devem estar presentes.
---
# Etapa 1 — Identificação
Nesta fase a equipe compreende o problema ou oportunidade que dará origem ao projeto.
Objetivos:
- compreender a necessidade da comunidade;
- identificar o público-alvo;
- definir o propósito da ação;
- delimitar o escopo.
Perguntas orientadoras:
- Qual problema queremos ajudar a resolver?
- Quem será beneficiado?
- Por que este projeto é relevante?
- O que está ao alcance da equipe durante o semestre?
Produtos esperados:
- descrição do problema;
- justificativa;
- objetivos iniciais;
- proposta preliminar.
---
# Etapa 2 — Planejamento
Nesta fase o projeto é estruturado.
Dependendo da modalidade escolhida, podem ser elaborados:
- plano de trabalho;
- cronograma;
- definição de responsabilidades;
- levantamento de recursos;
- orçamento (quando necessário);
- plano de comunicação;
- análise de riscos;
- plano de acessibilidade;
- plano de segurança;
- indicadores de sucesso.
O planejamento deve ser suficiente para orientar a execução.
---
# Etapa 3 — Preparação
Nesta etapa a equipe produz todos os recursos necessários.
Exemplos:
- materiais didáticos;
- identidade visual;
- formulários;
- sistema de inscrições;
- jogos;
- softwares;
- documentação;
- apresentações;
- equipamentos;
- materiais de divulgação;
- testes;
- validações.
Ao final dessa fase, o projeto deve estar pronto para ser executado.
---
# Etapa 4 — Execução
Nesta etapa ocorre a realização do projeto.
Dependendo da modalidade, isso pode envolver:
- realização de eventos;
- oficinas;
- prestação de serviços;
- entrega de produtos;
- atividades educativas;
- ações comunitárias;
- apresentações;
- implantação de soluções.
A equipe deve acompanhar continuamente o andamento da execução.
---
# Etapa 5 — Documentação
Toda atividade realizada deve gerar evidências.
Exemplos:
- fotografias;
- vídeos;
- listas de presença;
- registros de reuniões;
- versões dos materiais;
- formulários;
- produtos desenvolvidos;
- registros institucionais;
- feedback dos participantes.
A documentação não deve ser deixada apenas para o final do semestre.
Ela deve ser produzida continuamente.
---
# Etapa 6 — Avaliação
Após a execução, a equipe analisa os resultados.
Aspectos que podem ser avaliados:
- alcance dos objetivos;
- participação do público;
- qualidade da execução;
- impacto percebido;
- dificuldades encontradas;
- efetividade das soluções adotadas.
Sempre que possível, utilizar evidências objetivas.
---
# Etapa 7 — Reflexão
A reflexão é parte obrigatória do processo extensionista.
A equipe deve discutir:
- o que funcionou bem;
- o que poderia ser melhorado;
- quais conhecimentos foram aplicados;
- quais competências foram desenvolvidas;
- qual foi o impacto para a comunidade;
- qual foi o impacto para a formação acadêmica.
A reflexão deve conectar prática e aprendizagem.
---
# Organização das Equipes
Cada equipe deve definir responsabilidades claras.
Exemplos de funções:
- coordenação;
- comunicação;
- documentação;
- logística;
- desenvolvimento técnico;
- relacionamento com parceiros;
- divulgação;
- avaliação.
As funções podem variar conforme o projeto.
Não é necessário que todas existam em todos os projetos.
---
# Gestão do Projeto
A disciplina não pretende ensinar metodologias formais de gerenciamento de projetos.
Utilizar processos simples.
Toda equipe deve manter, no mínimo:
- lista de tarefas;
- responsáveis;
- cronograma;
- registro das reuniões;
- acompanhamento do progresso.
A simplicidade é preferível à burocracia.
---
# Checkpoints
Ao longo do semestre devem existir checkpoints regulares.
Cada checkpoint deve responder às seguintes perguntas:
- O que foi realizado desde o último encontro?
- O que será feito até o próximo?
- Existe algum impedimento?
- O planejamento continua válido?
- É necessário ajustar o cronograma?
O objetivo dos checkpoints é orientar o projeto, e não fiscalizar os estudantes.
---
# Gestão de Riscos
Toda equipe deve identificar riscos relevantes.
Exemplos:
- atraso no cronograma;
- indisponibilidade de parceiros;
- problemas técnicos;
- baixa participação;
- falta de recursos;
- conflitos internos.
Sempre que possível, definir estratégias de mitigação.
---
# Acessibilidade
Todo projeto deve considerar acessibilidade desde o planejamento.
Sempre avaliar:
- acessibilidade física;
- acessibilidade comunicacional;
- acessibilidade digital;
- inclusão de pessoas com deficiência;
- linguagem acessível.
A acessibilidade não deve ser tratada apenas como um requisito burocrático.
---
# Segurança
Projetos presenciais devem considerar aspectos básicos de segurança.
Dependendo da atividade, avaliar:
- capacidade do espaço;
- circulação de pessoas;
- equipamentos;
- energia elétrica;
- prevenção e combate a incêndio;
- procedimentos de emergência.
---
# Relação com a Comunidade
A comunidade deve ser tratada como parceira do projeto.
Evitar desenvolver ações apenas para cumprir requisitos da disciplina.
Sempre buscar:
- diálogo;
- respeito;
- escuta;
- colaboração;
- benefício mútuo.
---
# Papel do Professor
Durante o desenvolvimento do projeto, o professor atua como mentor.
Suas responsabilidades incluem:
- orientar as equipes;
- acompanhar o progresso;
- fornecer feedback;
- apoiar a resolução de problemas;
- garantir alinhamento com os objetivos da disciplina.
O professor não deve assumir responsabilidades que pertencem às equipes.
---
# Critérios de Qualidade
Independentemente da modalidade escolhida, um bom projeto extensionista deve apresentar:
- objetivo claramente definido;
- relevância social;
- planejamento consistente;
- execução organizada;
- documentação adequada;
- avaliação fundamentada;
- reflexão crítica;
- integração entre teoria e prática.
---
# Flexibilidade
Este guia descreve um processo comum para projetos de extensão.
Ele deve ser adaptado conforme:
- modalidade da ação;
- público-alvo;
- recursos disponíveis;
- cronograma;
- contexto institucional;
- necessidades da comunidade.
As adaptações devem preservar o ciclo completo da extensão universitária.
---
# Princípio Fundamental
O sucesso da disciplina não deve ser medido apenas pela qualidade do produto final.
O principal objetivo é que os estudantes vivenciem, de forma planejada, responsável e reflexiva, todas as etapas de um projeto de extensão universitária, compreendendo seu papel como profissionais e cidadãos comprometidos com a transformação da sociedade.
